# 离线导航取消策略收敛（2026-11-02）

本轮只在笔记本工作空间修改、编译和回放验证。没有连接 NX，没有同步、编译或重启任何远端节点；没有启动物理速度桥接。

## 修改结果

- 将规划器的定位可用性心跳从 0.5 秒统一为 1 秒，明确区分未收到、心跳过期、实际 false 和时钟异常；诊断带心跳年龄。
- 删除运行期间“发现未就绪就直接取消”的独立决策入口，交由定位适配器按原因选择等待或取消。启动前旧目标、时钟回退等屏障保留。
- 心跳迟到、源数据过期、缺少同时间里程计、定位确认等待、定位恢复后的第一帧实时障碍等待，使用同一个有界停车恢复窗口。规划器反射回来的旧 false 不再凭自身覆盖实际定位原因。
- 恢复等待由 3 秒改为 10 秒，两个生产行为树的输入等待由 5 秒改为 12 秒。原因切换、坏帧、请求重试均不续期。恢复必须通过原有新鲜度、位姿修正限制以及当前路径的独立复验，期间不缓存和重放速度。
- 单条坏格式、错帧、无效姿态和乱序输入丢弃，不撤销仍新鲜的上一条有效状态，也不刷新它的接收时间、源时间或处理进度。状态 JSON 使用事务式提交；乱序 true 不覆盖明确 false。
- 缓存定位结果到期统一走 alignment_expired，避免 timer 调用顺序使同一到期事件变成硬取消。明确地图 false 持续保留 map_not_ready，不误转成心跳缺失。

## 保留的限制

- 里程计 0.5 秒、本地地形 1 秒、全局障碍成功消费 2 秒、当前定位 3 秒的有效性要求保持；本地代价地图观测期限仍为 0.8 秒。
- 全局匹配结果 6 秒、全局复验 12 秒保持。
- 地图明确无效或身份冲突、歧义定位、超限位姿修正、LIO/EKF 明确不一致、真实 ROS 时钟回退、用户取消仍停止并结束任务。连续输入故障超过恢复窗口仍取消。
- 碰撞检查、机器人轮廓、速度补偿和地图文件未调整。
