## 源码中仍存在的窗口

1. `Astar3DPlanner::createPlan` 在搜索完成后读取一次当前位姿，再做地图锁、投影、地形/矩形复核和增密，最后返回。此阶段及传输中机器人仍可能前进；“refreshed”日志时间不等于所采用位姿的精确采样时间。
2. 1.1.20 Shim 的 `getSampledPathPt()` 始终从 `current_path_.poses.front()` 量 0.15m；它没有以控制时刻的机器人投影为前视起点。所选点会以最新 TF 转到 base_link。机器人前移越过该点后，该点就可能出现在身后，改变对齐方向。
3. 控制器收到新路径而进入旋转后，平滑器不会瞬时消除已有线速度，这会继续消耗前视余量。以理想匀减速估算，0.4m/s、0.7m/s² 的停车距离约 0.114m；0.6m/s 时约 0.257m。这是机制说明，不是本次实测停车距离。
4. `planningStartMatchesRobot` 的 XY/Z 0.10m、yaw 0.20rad 门槛不满足时会按显式起点保留请求值，当前缺少跳过重锚的原因日志。没有发现直接路径或缓存早返回绕过统一的 createPlan 后处理。

稳健修复方向是在 Shim 计算时依据当前位姿裁掉已走前缀，选择剩余路径的前视点，同时保留真实后方目标及必要绕行。不能仅通过强行把所有身后点删除来改变有效路径。当前尚未修改此行为。
