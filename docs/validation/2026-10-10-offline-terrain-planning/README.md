人工坐标链为 `map → odom → base_link → body`。本体位姿设为离地 0.50 m，匹配配置 `lio_height_offset=-0.50`；这些是测试输入，不是新的真机测量或外参标定。

## 发现并修复的问题

首次完整场景测试中，其余 6 个场景通过，6° 缓坡失败。地形节点已输出 622 个支撑点、0 个危险点，规划器仍报不连通。修复前的重复日志已清理，问题结论保留如下。

原因：支撑网格间隔 0.20 m，路径检查却插入 0.10 m 中间采样列。中间列从附近支撑点复用高度，后续实际高差被除以采样列间距，导致 6° 坡被误算为约 12°。

`Astar3D::segmentTraversableImpl()` 现在按相邻实际支撑网格的 XY 距离计算坡度。每个中间采样点仍检查有限范围内的支撑与障碍，坡度和台阶阈值没有放宽。新增 5 项回归覆盖 6° 坡双向搜索及缓存刷新、略超 10° 的坡、0.16 m 台阶、大段缺口、中间列障碍。原有 38 项与新增 5 项，共 43 项全部通过。

地形模块增加诊断及 8 项回归，已有与新增共 18 项全部通过。每 2 秒节流日志新增：

| 日志字段 | 含义 |
| --- | --- |
| `support` | 输出的可通行地面支撑点数 |
| `analysis_ms` | 地形分析耗时 |
| `cells_observed` | 有输入点的地形格数 |
| `cells_unobserved` | 没有输入点的地形格数 |
| `reject_fit_neighbors` | 拟合邻域不足的格数 |
| `reject_fit_degenerate` | 点分布退化、不能拟合的格数 |
| `reject_support` | 拟合点数不足的格数 |
| `reject_slope` | 坡度超限的格数 |
| `reject_rmse` | 平面拟合误差超限的格数 |
| `reject_step` | 平面检查通过、相邻高度突变超限的格数 |

每个已观测格只计入一个最终结果。多个条件同时失败时按原判断顺序计数。本次 16 cm 台阶先被坡度条件拒绝，`reject_step=0` 不表示台阶可通行。没有观测到地面的格不直接等同于障碍格。
