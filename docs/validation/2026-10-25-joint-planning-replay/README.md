## 失败来源

| 分类 | 普通失败请求数 | 已取得的依据 |
| --- | --- | --- |
| 起点附近矩形外廓碰撞 | 5 | 固定地图危险点；原导出来源均为 measured |
| 终点朝向外廓碰撞 | 3 | G6 三次均关联同一固定地图 synthetic 标记 |
| 搜索不连通 | 1 | 直线候选遇到实时实测障碍；完整搜索失败原因未唯一确定 |
| 无安全目标地面 | 3 | 服务端原始错误已匹配；没有更细的结构化拒绝原因 |

9 个结构化失败诊断中，8 个来自 `/offline_map/obstacles`，1 个来自
`/terrain/obstacles_global`。静态来源又可对应到导出文件的 5 个 measured、3 个 synthetic。
measured 表示导出的测量危险点，synthetic 表示地形算法生成的危险标记；这些分类本身
不能证明现场确有障碍或地图误判。这里统计的是请求次数，不是独立危险点数量。

G6 的三次失败均关联地图点约 `(5.2, 0.8, -0.240303)`，原始记录为
`maps/lab_v1_navigation/hazard_sources.csv` 第 845 行。所属 tile 含多种拒绝原因，
不能用 tile 聚合统计断定这个单点的具体生成原因。后续可优先复核这里的地形分类。

“无安全目标地面”也不能直接等同于地面点太少。候选可能因支撑、高度或占用被拒绝，
本轮 3 次尚缺逐候选的细分数据。

本轮查询没有定位门控失效或超时的证据。回放数据结束后出现 odometry_missing，

终点相对原目标的 XY 偏移为 0～0.166 m，末端 yaw 偏差为 0；这些是算法输出的内部比较，
不是外部测量的到点误差。目标地面投影和保留的起点连接沿用现有参数。

## 这次新增的工具能力

- `validate_replay --planning-cases FILE`：在真实传感器回放上仅增加全局规划器。
- 离线入口和评测共用 `offline_planner_settings()`，避免地图身份或连接参数配置不一致。
- 固定目标、检查时刻及原始来源保存在 `replay_planning_cases_lab_v1.yaml`，未根据结果删改。
- 使用回放 TF 查询真实起点，不发布假 ready、假传感器或固定机器人 TF。
- 保存计划时刻、实际请求时刻、延迟、原始目标、起点 TF、返回路径和终点偏差。
- 未就绪、未执行、拒绝、超时和成功分别统计；超时后阻断后续查询，避免旧请求串入新请求。
- JSON 保留完整输入快照；CSV 逐请求导出。Humble Action 没有错误码时，按串行次序及
  原目标坐标匹配服务端错误原文。本轮 15 个失败（含负对照）均匹配，未匹配项为 0。
  重复目标的日志缺失、多余或顺序不符时保留歧义，不猜测归属。
- 自动备份并恢复 FAST-LIO 源码调试日志，收尾已核对原始字节。测试进程已结束。

当前节点链路为真实录包 → FAST-LIO/EKF/地形 → 重定位/定位适配器 → 全局规划器。
没有启动控制器、行为树、恢复行为或运动桥接，`/api/sport/request` 发布者为 0。
机器人的位姿始终跟随录包轨迹，不会沿新生成的路线运动。

## 复用命令

输出目录必须是新目录。此目标配置固定了当前 lab_v1 的地图 ID，换地图需要另写目标配置。

```bash
source /opt/ros/humble/setup.bash
source /home/zyhtxdy/go2-w_ws/install/setup.bash

ros2 run go2_offline_navigation validate_replay \
  /home/zyhtxdy/go2-w_ws/bags/go2_inputs_20261010_094309 \
  /home/zyhtxdy/go2-w_ws/maps/lab_v1_database \
  /home/zyhtxdy/go2-w_ws/maps/lab_v1_navigation \
  /home/zyhtxdy/go2-w_ws/docs/validation/新的联合评测目录 \
  --domain 155 \
  --planning-cases /home/zyhtxdy/go2-w_ws/src/go2_offline_navigation/config/replay_planning_cases_lab_v1.yaml
```

工具自动隔离到本机 ROS 域并清除自定义 DDS 配置。录包不会暂停等待规划，各目标实际
普通目标派发比组检查时刻晚约 0～0.84 秒；含负对照时最大为 1.002 秒。
原始延迟完整保留。不同请求的起点略有差异。
