# 终点采样与高度检查修复

2026-10-28 开始修改，2026-10-29 继续完成。本轮只在本机修改、编译和回放，没有连接 NX，没有启动机器人运动。

## 修改内容

### 终点采样

离线模式保留原请求精确 XY 和原栅格中心的优先级；这些候选没有可执行路径时，再在原目标容差内细化候选。默认 0.1 m 栅格中采用 8×8 的格内采样，没有扩大原有 0.2 m 目标容差。

终点位姿和接入路径分开处理：

- 终点必须有现有地面支撑，并通过原矩形外廓检查。
- 完整路径可以由普通搜索及连续验证接入该终点。
- 另生成从附近安全搜索节点接入终点的直线连接，避免要求车身先经过一个碰撞的终点栅格中心。
- 连接不使用起步盲区豁免，逐段验证地形、坡度、高差、障碍与终点转向。连接长度上限由原车身长度推导，当前不超过 1.5 m。
- 同一搜索节点保留多个终点选项，终点转向不合适时可以继续尝试其他位置。

采样和接入连接有数量上限：每个地面列保留至多 4 个候选，全局至多 32 个格内终点、512 次连接检查和 64 条已检查的连接。数量上限是计算约束，不表示穷尽连续空间。

同一不可变地图快照中的连接复用其已验证的平移和终点转向结果，搜索仍检查新的到达朝向。返回路径前仍在最新实时地图上重新检查整条路径。没有降低车身尺寸、删除占用点或取消真实碰撞保护。

### 高度检查

矩形扫掠、地面净空、起步连接、连续路径验证和障碍软代价统一依据：

`世界地面高度 + 配置车高`

计算最高检查体素，不再直接将向上取整的车高格数加到地面格编号。原配置 `robot_height: 0.75` 未修改。旧的整数格数接口保留兼容；规划器传入以米表示的车高进行精确上界计算。

连续升降时保留垂直采样包络，防止修正上界后漏掉采样点之间的顶碰；低矮障碍和相交的顶部体素继续阻塞。

原索引 191 的冻结数据，修复前命中 Z=0.4～0.5 m 的体素，而配置车身顶部为 Z≈0.373 m。修复后同一条短连接通过，见 `recorded_height_after.json`。这是相对于当前配置的几何修复，不代表加装雷达后的整机外廓已经实测标定。

### 原成功请求 118 本轮失败

这条新增拒绝没有从结果中删除：

- 原请求发生在约第 40.48 秒，本轮在约第 43.26 秒。
- 原请求起点约为 (0.009,-0.006) m，朝向约 1.018 rad；本轮约为 (0.143,0.122) m、0.228 rad，均为软件观察值。
- 本轮拒绝引用新鲜实时回波 `(3.573,-0.400,0.287)` m；它来自当时的 `/terrain/obstacles_measured_global`。
- 将前后两个起点分别放回同一固定地图，当前程序均能返回完整路径，见 `frozen_input_checks.log`。

这说明它不是同起点、同实时障碍的严格回归对照。现有证据不能把它简单归为代码退步，也不能据固定地图检查证明当时真实动态场景一定可通过。

### 计算开销

本轮主回放查询耗时中位数约 0.032 s，95 分位约 0.955 s，最大约 1.193 s。上轮对应约 0.036、0.634、0.816 s。细化终点会让部分原先直接拒绝的请求进入完整路径搜索，长尾耗时有所增加；本轮不声称整体搜索速度提高。

主回放的 8 次未执行请求正是需要保留的测试限制，已单独补测。没有延长传感器时效阈值来掩盖计算开销。

## 尚未解决或未验证

- 剩余碰撞和转向拒绝仍需继续核对，不能认定全部是实体障碍，也不能统一认定为误报。
- XY 方向仍使用完整体素占用，保留了已有的保守性。
- 细化采样和连接搜索有数量及时间限制，不能保证找到所有连续空间中的可行姿态或路线。
- 本轮没有运行控制器、速度桥接或真机跟踪，未验证机器人实际通过窄通道。
- 原配置车身尺寸和雷达外参的现场标定不在本轮完成范围内。
