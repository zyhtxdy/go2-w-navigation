## 冻结地图上的 MPPI 复算

使用本机安装的实际 Nav2 MPPI 优化器库、记录下来的控制参数、原始 inflated costmap、TF 位姿和融合速度。将已发布全局路径转到 odom，按记录的 1.5m 前向裁剪范围提供给优化器。每个冻结输入固定机器人状态，执行 12 次优化迭代。

**这是冻结输入实验，不是原始随机序列、控制器历史或动态行人的逐位复现，更不是真机成功率。** 全局路径这里是直线，实验只研究当前位置附近的局部优化；没有运行 Shim、平滑器、速度补偿或运动接口。

录包第 18.02s 对应的冻结图：

| 离线设置 | 最后一批采样中最大横向偏移 | 最后优化轨迹最大横向偏移 |
| --- | --- | --- |
| 原参数，wz_std=0.45、2.5s | 0.0464m | 0.00107m |
| 仅 PathAlign 权重改为 0 | 0.0464m | 0.00107m |
| 仅 wz_std 改为 0.70 | 0.0746m | 0.00098m |
| 仅预测时长改为 4s | 0.1050m | 0.00176m |

表中采样最大值包含可能碰撞的候选，不能当作可安全绕行幅度。原参数最后一批仍有 909 条候选通过独立完整矩形检查，多为停留或微小移动，所以优化器不需要报“全体碰撞”；有可行停车解不等于找到了绕行解。

第 13.92s、21.02s 的冻结输入也表现为极小的优化侧向偏移。第 24.92s 更靠近障碍，测试动作族的可用空间进一步缩小；这些实验没有证明所有其他动作都不可能。

## 局部地图是否完全没有绕行空间

另外枚举“原地转向—斜向移动—转回—继续前移—返回原起始平行线”的几何动作，在冻结局部地图上逐步调用安装版 Nav2 的矩形碰撞检查器。使用记录的车体 0.80×0.50m，padding=0，每 25ms 采样，不删除障碍、不缩小车体。

- 18.02s 的冻结图中，测试动作族找到了 25 条通过完整几何检查的侧绕并返回动作。
- 13.92s、21.02s 的冻结图中，也存在通过的动作。
- 24.92s 的冻结图中，该动作族没有找到通过的完整动作；这不是不存在其他路径的证明。

这只是二维局部地图上的几何可行性，不验证地面支撑、动力学、执行误差和行人的后续运动；不能据此保证真机可以按这些动作执行。检查结果和示意图见 `frozen_geometric_bypass.png`、`frozen_runs/*.geometric_bypass.csv`。

## 结论与修复方向

本趟证据更支持：MPPI 在前方临时障碍处陷入停车附近的局部解，独立噪声未产生足够大的、持续同向转弯起步。感知到了障碍，保留参考线的协调逻辑也工作了；未发现全局先换路打断这一次绕行。仅放大角速度标准差、去掉 PathAlign 或延长到 4s，没有解决该冻结输入中的停车解。

后续应优先研究时间上连续的转向采样或独立的左/右绕行候选，并在停滞时让全局规划提供侧绕引导。不能直接把单个转向种子作为补丁上线：试验中转向种子能扩大侧向探索，但部分优化后的平均轨迹仍被完整矩形复核判为碰撞。因此任何采样改进都须同时验证最终输出轨迹，不能只验证采样中的个别轨迹，也不能关闭碰撞检查强行通过。

当前未修改任何生产导航实现或默认控制参数。
