# 膨胀半径与旧控制参数的冻结输入对照

全部在本机离线执行，没有连接 NX、修改生产参数或发布运动指令。材料来自同一趟行人进入前方后停车的录包，不是新增真机测试。

## 方法

固定第 13.92s、18.02s、21.02s 的机器人位姿、融合速度、当前 Go2 矩形车体、已观测致命格位置及参考路径。每个输入执行 12 次冻结优化迭代。

膨胀对照使用实际安装的 Nav2 InflationLayer，从相同致命格重建软代价。控制组 radius=0.5、scale=4 的结果与原记录地图基线一致。其他组只改变半径或衰减因子；矩形外廓不变。优化结果另用实际 Nav2 完整矩形检查器逐点复核，不依据中心格是否有软代价判断安全。

旧控制参数组从 `ros2_fy_ws/src/nav2/fy_nav2_bringup/config/nav2_mppi_params.yaml` 提取 FollowPath，仍使用 Go2 这次记录的车体、地图和状态。它不是 Scout 真机重演，也没有重建 Scout 原来的感知、底盘响应和优化器历史。旧工作空间安装配置链接指向当前不存在的 `/home/bz/...`，只能核对现有源码，不能确认历史运行实际加载值。

## 对用户假设的判断

- `inflation_radius=0.5` 并不会使障碍刚进入 4m 局部地图时，机器人中心格立即具有高代价；它限制的是障碍附近的代价场范围。
- 18.02s 冻结图机器人中心格实际为 0，矩形边缘代价为 253，并非 254 致命碰撞。
- 当前 Humble CostCritic 的零中心格跳过和基于外接圆代价阈值的完整外廓检查确有耦合。当前矩形半长 0.4m、半宽 0.25m，外接圆半径约 0.472m；直接恢复旧 0.35m 半径会削弱该快捷判断的覆盖。
- 改衰减系数能单独改变软代价，但本次 4→6/8 的冻结对照并未解决停车局部解。

后续应把几何碰撞判定从软膨胀代价中分离，再独立调整避障偏好；稳定侧绕还需要持续转向候选和最终输出轨迹复核。没有在本次诊断中修改生产 MPPI。
