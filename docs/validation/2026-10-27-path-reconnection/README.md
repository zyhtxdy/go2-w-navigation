# 2026-10-27 旧路径前向重接

本轮只在本机修改、编译和运行软件检查，没有连接或同步 NX，没有启动机器人运动控制或下发速度。保持全局搜索、速度、倒车模式、车身尺寸和地图参数。

## 问题与改法

原 `selectStablePathSuffix` 输出实际机器人位置、旧路径最近投影点、剩余旧路径。机器人只横向偏离几厘米时，这个短连接可能要求检查器先转约 90° 接回，再转回沿原方向前行。

缓存复用原来还有一次专属的“直接连到终点”简化；路径有效性检查没有同样处理。因此两处检查可能采用不同的重接方式，窄处的横向假想转向也容易触发失败。

现在缓存复用和 `/terrain/is_path_valid` 共用 `reconnectAndValidateSuffix`：

1. 仍按原折线和既有单调进度找到最近投影，另保存投影位置。
2. 在投影后的当前近直线段内，尝试最多 4 个前向接入点，前视上限 0.6 m，远到近。
3. 候选接入点相对首段切线变化超过 0.05 rad 时停止，保留后续拐角和完整旧尾段。小角度变化比较的是首切线，不会靠多次小转角累计绕过明显拐角。
4. 每个候选都包含实际机器人 XY，按原路径间距重新采样，再检查完整连续地面和矩形平移、转向、末端旋转。
5. 没有可用的前向连接时，对原投影连接执行同样检查；仍不通过就拒绝复用或判路径失效。

前向尝试有约 50 ms 的阶段间预算，单次完整检查和最终原连接另计；这不是整个规划服务的硬实时上限。关闭完整矩形检查时不尝试这些新前向连接，保留原连接策略。

## 保持的约束

- 实际起点、整条新连接和保留尾段都进入同一校验，不能跳过当前真实碰撞或尾段新增障碍。
- 高度、坡度、台阶、原有受限盲区连接和实时数据健康门控继续生效；没有新增碰撞豁免。
- 前视接入点不是已经走过的位置。进度仍只由机器人对原折线的投影推进，重复检查同一位姿不会不断消耗前视距离。
- 新连接首点为实际机器人 XY，旧路径终点保持；缓存复用使用本次请求的起点和目标朝向，而非旧目标朝向。
- 路径有效性检查验证存在完整安全的本地重接方式，返回的仍是 `IsPathValid` 结果；它不下发速度。局部控制器的实际轨迹检查仍保留。
- 本轮限制的是前视连接不另跳后续支路；原有全折线最近投影的关联规则没有重写，不声称解决所有相近重叠支路的关联问题。

为避免重复计算，缓存调用方不再额外重做同一矩形检查。完整检查失败的报告独立复用，保留原失败阶段、碰撞位置、朝向和来源。路径替换前的目标位置改为值拷贝，避免旧引用在替换后失效。

## 验证结果

本机 Release 编译 `astar_3d_planner` 和 `navigation_bringup` 成功。完整软件检查 **253 项规划器测试、1 项插件加载测试全部通过**，无失败、错误或禁用。新增 10 项核心几何/连接检查和 4 项公开插件检查包含在上述总数中，不是真机测试趟数。

| 场景 | 检查结果 |
| --- | --- |
| 近墙小横向偏移，最近投影要求大转向 | 原横向连接矩形拒绝，前向接入完整检查通过 |
| 当前实际车身已碰墙 | 所有新候选仍拒绝，首点不被移走 |
| 连接内侧有障碍或后续旧路径新增障碍 | 完整路径检查拒绝 |
| 90° 拐角、交叉路线 | 前向候选不越当前段，后续旧路线保留 |
| 重复在同一位姿重接 | 进度只记录实际投影，不按接入点推进 |
| 关闭优化或偏移不超过 1 mm | 检查原后缀，不生成新前向接入 |
| 旧稀疏地图中已验证的起点连接 | 原公开插件回归继续通过 |
| 实际 `/terrain/is_path_valid` 服务 | 近墙小偏移返回有效；真实当前碰撞和远处尾段障碍仍无效 |
| 实际缓存复用分支 | 确认 `reused stable` 日志，完整外廓通过，保留尾段及本次目标朝向 |

几何案例使用软件构造的 0.05 m 栅格、0.82 × 0.52 m 含余量矩形和窄走廊，不是机器狗实测轮廓或通道通过结果。

缓存集成案例：有限走廊出口后有转向空间，初次路线绕出口到目标；第二次起点横向偏移 0.02 m。原最近投影连接及直接连终点都发生矩形碰撞，新实现复用旧路线并前向接回。第二次要求的目标 yaw 改为 0.2 rad，返回方向与其一致，且整条矩形检查通过。

本次日志中初次搜索返回 53 点，缓存复用返回 47 点，缓存过程约 0.012 秒；这是本机单次软件计时，不能推断 NX 性能或真机成功率。

既有日志中真实新鲜障碍、数据过期、定位超时和实际控制响应的问题，不能由本轮软件案例宣布解决。仍需后续真机记录对照。
