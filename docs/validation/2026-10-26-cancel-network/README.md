## 取消的直接依据

当前这次运行的日志中，记录到 16 次导航门控从就绪变为失效：14 次 localization_global_verification_timeout、1 次 stale_or_future_alignment、1 次 lio_ekf_planar_disagreement。bt_navigator 中有 17 条 Goal canceled；两组计数不是独立实车任务数，不能逐项简单等同。

后台全候选匹配多次耗时约 3～3.5 秒，出现 accepted_stale_seed_only 或 foreground_consumed_stale_result；结果刚完成就超过 3 秒接收预算。即使当前轻量跟踪年龄仍约 0.2 秒，8 秒内没有通过接收的全局复核也会使定位无效。适配器随后请求取消导航并停止发布有效 map→odom，点云消息因此可能等待 TF 而无法显示。

典型日志：1792996495.341 发生 LIO/EKF 不一致，1792996495.412 目标取消；随后 controller 的 map/odom 查询请求比最后可用 TF 新约 27 毫秒。1792996509.525 又发生全局复核超时；到 1792996576.843，查询仍请求旧公共 TF 时间 1792996509.512，而 base_link 缓存最早已到 1792996566.823，因此报向过去外推。

RViz 的 frame 'odom' 表示消息坐标系，不足以证明报错来自 /odom 话题本身。消息队列满可以由缺少相应 map→odom 变换引起，不能只通过增大队列或更换 QoS 解决。本次不能凭日志还原每条原始里程计消息的实际延迟。

## 已修改的行为

将维护阶段后台结果的接收预算独立为 max_global_result_age，默认 4 秒，并由全局复核期限上限约束。首次定位及当前跟踪帧仍采用原 3 秒新鲜度；发布当前位姿前仍必须匹配当前扫描，通过质量和变换跳变检查。前台计算完成后再次检查后台结果年龄。后台结果保留真实测量时间，不能改成当前时间；8 秒全局复核期限、3 秒跟踪超时和质量、歧义等检查保留。

LIO/EKF 平面不一致仍触发保护；已新增 XY、yaw 差值、阈值、双方时间戳及采样时间差日志。旧日志缺少这些数值，因此本轮没有猜测性地抬高阈值。
