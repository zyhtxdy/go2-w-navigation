# 独立离线地图导航本机验证（2026-10-14）

本轮只在本机实现和验证，没有连接、同步或操作 NX，真机测试 0 趟。
合成场景和软件控制输出不能证明真实隧道的定位精度、巡检成功率或停车性能。

新增入口 `go2_offline_navigation/offline_nav.launch.py`；原在线入口继续使用原命令。
原融合 launch 的 `publish_map_odom_tf` 默认 true，离线入口显式关闭。
离线入口复用现有 FAST-LIO/EKF/实时地形，与同一已知点云地图生成的固定支撑和障碍配合。
重定位原型保持观察输出，由新适配器独占 map→odom、检查定位状态并过滤导航速度。
运动桥接默认关闭，仿真时钟下禁止开启物理桥接。

## 结果

| 检查 | 结果 | 范围 |
| --- | --- | --- |
| A* 及地图回归 | 91 项通过 | 包含原 86 项和新增 5 项静态地图检查 |
| 导航行为树插件加载 | 1 项通过 | 本机补齐依赖后编译的插件 |
| 离线地图与 ROS 联调 | 8 项通过 | 文件校验、定位门控、实际规划器、完整入口 |
| 完整离线入口 | 通过 | 真实重定位节点处理合成点云；Nav2 服务激活 |
| 下发 NavigateToPose | 通过 | 得到规划路径和软件控制输出；目标随后取消 |
| 狗运动接口 | 没有启动发布者 | 隔离 ROS 域内验证 /api/sport/request 发布者为 0 |
| NX / 真机 | 没有执行 | 未同步、未编译、未移动狗 |

实际规划器在静态地图加载后成功规划；加入实时障碍后成功绕行，清除实时障碍后仍成功。
定位无效时拒绝规划。地图加载初期的无支撑拒绝属于预期启动状态。
初次联调还发现静态支撑的 FLOAT32 网格边界误差会造成假断连，已在离线模式稳定体素键，
没有更改在线模式量化方式，也没有扩大默认连接半径。

测试使用 ROS 域 109、仅 localhost、Fast DDS；所有自启进程在检查结束后关闭。
完整联调使用合成传感器、外部模拟的里程计/TF，不启动真实雷达驱动或物理运动桥接。
本机新增安装了 Nav2 bringup、MPPI、转向控制器等 71 个依赖包，没有升级已有软件包。
