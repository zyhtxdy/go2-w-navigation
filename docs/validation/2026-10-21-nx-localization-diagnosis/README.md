输入在 NX 内部及时到达，而部分匹配的计算时间已经超过 3 秒新鲜度上限。
结果会在重定位节点完成时被丢弃；适配器没有新有效定位，就停止更新 `map→odom`。
这能解释本机 RViz 等待坐标变换、队列满以及缺少地图定位链路的报错。
当前配置每次采样都是全局搜索；搜索超时后继续搜索，使高计算负担持续。
下一步应针对候选计算开销和全局复核／轻量跟踪的调度优化，并验证误定位约束。
