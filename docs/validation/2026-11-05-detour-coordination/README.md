# 2026-11-05 局部绕行协调与重规划起点修复

本次修改、编译和验证均在笔记本工作空间完成。未连接 NX，未修改远端容器，未下发机器人运动指令。

## 1. 绕行时的职责分工

原来的剩余路线复查先检查整段矩形，随后才跳过近场。因此近场实时障碍挡住参考线时，可能在 MPPI 绕行前连续触发全局重规划；超过 0.30m 的侧向偏移也会被当成路径失配。

现在分开两种检查：

| 服务 | 用途 |
| --- | --- |
| `/terrain/is_path_valid`、`/terrain/is_path_valid_detailed` | 严格检查；保留给恢复和显式安全检查调用方 |
| `/terrain/is_path_valid_reference` | 行为树判断是否继续保留参考路线，允许有限的局部绕行 |

两个导航行为树均已接到 reference 服务。**Reference 返回 VALID 只表示参考路线可暂时保留，不保证沿这条原折线直接行驶无碰撞。** 实际局部运动仍由局部代价地图、Shim 和 MPPI 处理。

允许绕行前，先在完整地图上检查机器人当前实际矩形姿态。只有在私有参考快照中移除近场纯实测实时层障碍后，路线仍满足完整地形/矩形检查，才可暂时保留旧参考。静态地图、未知、合成、混合来源和远场障碍不被移除；同体素有静态所有权也不被移除。

过滤只发生在私有参考快照，真实地图、局部代价地图、初始全局规划和发布新路线前的完整检查均保持原有障碍。这里的实时层表示观测来源，并没有识别人或物体是否运动。

新增初始调试参数：

| GridBased 参数 | 值 | 含义 |
| --- | --- | --- |
| `local_detour_max_deviation` | 0.75m | reference 检查允许的最大路径偏离；仍须通过保留障碍后的几何检查 |
| `local_detour_progress_timeout` | 4s | 没有足够平移或转向进展后请求重规划 |
| `local_detour_timeout` | 12s | 同一目标一次局部绕行的总预算 |

路径时间戳或容差投影终点变化不会重新计时；使用原请求目标记录预算。定位、TF、地图和障碍数据失效仍会拒绝通过，并在提交有效结果前再检查一次。当前地面高度取当前 LIO 地面参考及对应支撑层，避免拿旧路线高度检查当前车体。

## 2. 重规划起点落后

原 `createPlan()` 使用请求开始时的 start 完成整次搜索，返回前只更新时间戳。计算期间机器人继续运动时，新路径仍带旧起点；Shim 从路径开头取 0.15m 前视点，可能取到机器人后方。

现在对入口 start 与实时机器人 TF 相符的正常导航请求，在搜索结束后重新读取位姿，裁掉已走过的前缀并验证新的接入段。在线和离线分支都执行；返回消息、缓存与起点支撑层同步更新。显式指定其他起点的规划请求不会被任意覆盖，目标确实在后方时也保留正确转向。

这不是只替换 `poses[0]`：接入段、剩余路径以及最新地图中的完整矩形检查均需通过，否则拒绝发布。
