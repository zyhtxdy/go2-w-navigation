# 2026-10-27 圆形预筛与完整矩形检查一致性修复

本轮只在笔记本修改、编译和检查，没有连接或同步 NX，没有启动机器人运动控制或下发运动目标。在线和离线共用的规划插件已本机编译安装。地图、机器人外廓、目标容差、速度和倒车模式没有修改。

## 确认的问题

旧 `inflate_radius=0.24 m` 在 `resolution=0.1 m` 下向上取成 3 格。起点投影、终点候选、直达线、搜索和路径复核均用这份整格圆形占用地图提前拒绝。

构造的软件几何如下：障碍体素内侧位于 `y=-0.3 / +0.3 m`，精确直线为 `(.01,.01,.01) → (2.01,.01,.01)`；测试矩形为 `x=±0.41 m、y=±0.26 m`。完整矩形平移检查通过，但旧预筛把这条直线映射到 `y=0` 列后，因距上墙 3 格而拒绝。旧算法新增回归中可复现这一问题。

同一场景中，格中心位姿 `y=.05 m` 确实碰墙。因此不能将此案例说成“格中心 A* 路线原来被误拒”；问题是精确 XY 在格内偏移时，粗圆形占用代替了真实位姿判断。新实现放行进一步检查，并不声明格中心或者整格都安全。

上述是软件构造案例，不是真机通道尺寸或通行结果，也没有据此认定此前所有 1.1 m 通道失败都由圆形膨胀导致。

## 实现

完整矩形检查开启时，从 Nav2 已加 `footprint_padding` 的矩形包络推导以底盘原点为圆心的内切半径：

```text
r = max(0, min(-min_x, max_x, -min_y, max_y))
R = min(r, ceil(inflate_radius / resolution) * resolution)
```

硬预筛只保留满足 `resolution² × (dx²+dy²) <= R²` 的偏移，不再把派生的内切圆向上取整成更大的整格圆。底盘原点不在矩形内部时，半径为零并禁用这个初步拒绝；完整矩形检查保留。关闭完整矩形检查时，仍使用旧圆形膨胀。

其几何依据是：同尺寸栅格中，查询格内任意一点到障碍格的距离不超过两格中心距离；中心距离已经小于内切圆半径时，查询格内的真实底盘原点都必然发生碰撞，才能提前拒绝。数值比较不向外添加正 epsilon，避免扩大必要拒绝条件。

本机当前包络对应内切半径约 0.26 m，实际硬预筛半径约 0.26 m；完整矩形尺寸及其采样覆盖余量不变。配置的 0.24 m 仍保留避墙软代价范围。这个内部半径由包络自动推导，没有新增让用户手填的 ROS 参数。

实现共用原来的占用偏移维护逻辑，因此起终点、直线、A*、简化、密集复核、缓存和路径有效性检查读的是同一份预筛地图。完整矩形平移、拐角与末端旋转继续读取活动原始障碍体素。

## 软代价与诊断

- 从旧硬占用中释放的格仍被纳入原避墙软代价区域，避免这些位置变成零代价。
- 正向 A* 与反向启发式从观测地面的第一个车身格到车身顶部读取软代价，和路径优化保持一致，修复低障碍低于 `planning_height_offset` 时漏读代价的问题。
- 原点在外廓外、硬预筛禁用时，源体素的软代价保持有限正值；动态障碍增删及多来源软代价重算继续对称维护。
- 失败诊断新增 `prefilter_mode`（`rectangle_necessary` / `legacy_circle`）和 `hard_prefilter_radius_m`。原 `inflation_cells` 为配置圆的整格范围，不等于矩形模式的实际硬半径。
- 原始障碍证据可在硬预筛为空时直接查到，完整矩形碰撞诊断仍保留来源。

| 格中心确实能通过的通道 | A*、真实矩形动作检查和路径复核通过 |

新增回归的旧算法独立对照采用原算法源码，仅补一个未参与旧计算的配置字段以便相同调用编译。14 例中 5 例复现旧行为问题；同 14 例在新实现中通过。另加的低障碍代价案例和实际插件案例也均通过。

公开规划插件的软件直线案例日志记录 41 个路径点、约 2 m 路线、约 0.002 秒计算时间。这是本机单次软件计时，不是 NX 性能或真机通行率。

这次修复不增加亚栅格 A* 搜索节点；格中心路线真实碰撞而连续空间存在其他绕行路线时，仍可能需要后续局部细化搜索。没有执行真机验证。
