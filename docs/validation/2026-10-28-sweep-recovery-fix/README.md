# 同一地图与录包：规划门控修复和目标批测

2026-10-28，仅在本机修改、编译和回放。没有连接 NX，没有启动控制器、运动桥接或行为树，没有真机运动。

## 修复内容

1. **离线规划搜索不再长时间占用实时地图。** 原来整个投影、搜索和回退阶段持有实时地图读锁，障碍处理线程需要写锁才能提交更新，存在搜索阻挡数据续期的条件。现在先复制一致的地图快照，再在快照上搜索。实时障碍线程可继续更新。
2. **返回路径前检查最新地图。** 搜索结束后重新检查定位、地图代际和障碍流健康，并在当前地图上复核地形与完整矩形扫掠。新障碍可以否决旧快照的结果。没有延长数据有效期，没有降低碰撞标准。
3. **空闲观察不等待旧路径恢复。** 没有活动动作、也没有转发过非零速度的纯定位／规划模式，短暂输入过期只关闭就绪状态；数据恢复后不再强制验证残留 `/plan`。活动任务仍使用原有的有界等待、路径复核和取消保护；未知动作归属但已转发过运动的情况仍保守处理。
4. 规划诊断引用本次搜索的地图快照，最终复核诊断引用最新地图，避免碰撞证据与搜索数据混用。搜索后输入失效的异常区分定位、障碍流、地图代际和停用原因。

在线模式保留原有地图读取方式；本轮快照调整用于离线模式。没有修改速度补偿、机器人外廓或原地图文件。

## 编译和回归

580 项检查通过：规划器 308 项、行为树 12 项、离线导航 260 项。没有失败或跳过。新增覆盖：

- 持有规划快照期间，实时地图写入不被阻塞。
- 实时更新不改变已取得的快照；静态障碍和回波来源保留。
- 旧实测回波按原阈值过期，未知或合成来源不被错误清除。
- 快照中没有的新障碍在最新地图扫掠中仍被拒绝。
- 支撑更新或实时流重启使旧规划代际失效。
- 纯规划模式输入恢复无需验证旧路径；活动动作及未知来源运动仍受保护。
- 空闲期间迟到的旧动作状态仍触发取消保护。

最终整理诊断原因后再次编译并重跑 308 项规划器检查，通过。详见 `build_checks.log`、`all_checks.log`、`final_build.log`、`final_planner_checks.log` 和 `test_counts.json`。
