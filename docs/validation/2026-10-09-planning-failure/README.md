## 已识别的配置兼容性问题

我上一轮将规划 `max_slope_deg` 从 30 改为 10，同时保留了：

| 参数 | 值 |
| --- | --- |
| 体素分辨率 | 0.10 m |
| 支撑面连接最大水平距离 | 0.25 m |
| 坡度上限 | 10° |

`astar_3d.cpp` 的坡度判定使用离散高度差除以水平距离，没有消除高度量化误差。
不同高度体素的最小差是 0.10 m；即使使用最大连接距离，坡度角也至少为
`atan(0.10 / 0.25) ≈ 21.8°`，必然超过 10°。
因此，这组参数让不同高度层无法通过邻接边连接。
这是可从代码证明的配置问题，可解释日志中的一格高度层不连通；
没有实测数据证明所有安全目标失败都只由这一项引起。
应修正高度量化与坡度判断的配合，仍保留连续地面和碰撞检查。
