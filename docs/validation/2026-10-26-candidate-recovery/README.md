# 起点与终点候选恢复：2026-10-26～27

按用户要求完成两项全局规划修改：首选起点不连通时换安全起点；完整转向检查失败时保留其他容差内终点。10 月 26 日开始修改，10 月 27 日完成本机验证。没有连接或同步 NX，没有启动机器人导航控制或运动桥接，没有下发机器狗运动。

## 行为变化

### 1. 首选起点不连通后继续搜索

原流程选好一个局部可用起点后，普通 A* 不连通会直接抛异常；原有换起点策略仅在后面的部分矩形检查失败分支里生效。

现在普通搜索失败后也能尝试其他支撑起点。每条从实际机器人位置到备选起点的连接都要经过连续地面复核、原有高度差限制、当前障碍及完整矩形检查。在线和离线都可使用这套重试；离线既有的受限盲区连接开关不变，机器人本列已有地面时不能借换起点跳过地面大缺口。

仅当普通搜索完整耗尽 OpenList，才记录已证明无法抵达当前全部终点的可达节点，后续不再逐个重搜同一个孤立支撑片。搜索超时、节点上限、投影失败或朝向搜索失败都不产生这种剪枝。目标集合扩展后，旧集合产生的剪枝会清除。

### 2. 候选终点保留至完整动作检查

修复了三处过早丢弃候选：

- 备选起点重试原来只传入一个已选终点，现在对全部有效终点搜索；一个结果完整检查失败，会在同一起点继续尝试其余终点。
- 朝向搜索原来只传入一个终点，现在保留全部终点，并对到达方向、终点连接和末端转向检查；最终连续验证失败的终点可从当前尝试中剔除，继续检查其他候选。
- 精确目标位置可以静态放下车身时，旧逻辑会把附近所有支撑都合并成这个精确目标。但静态能放下不等于能完成进入和转向。现在保存不同栅格的附近位置作为延期候选，原路线失败后才启用。

仍然优先尝试原目标：初次普通搜索失败后，先在原终点集合下尝试安全起点，再启用延期终点，避免原目标仍可达时就提前停在容差边缘。延期位置要单独通过原有米制目标半径和终姿态检查；同 key 的投影中心不覆盖已保存的精确 XY。

选中其他终点后，路径末端、目标 key、地面高度、路径代价、诊断和缓存一并更新，末端朝向仍是用户请求的朝向。

## 预算与保留的限制

- 额外起点最多检查 8 个，起点和普通终点重试共用约 0.25 秒搜索预算；每次普通重试最多 50000 个节点，并在搜索循环内部检查剩余时限。
- 朝向恢复的多终点尝试共用原有约 0.35 秒预算，不为每个终点重新分配完整预算。
- 上述是搜索及阶段之间的预算检查，不是整个 `createPlan` 的硬实时上限；原始普通搜索、单次几何检查及后处理另有既有开销。预算不足会报告相应限制，不能声称已穷尽所有可能路线。
- 业务配置的目标投影半径仍为 0.2 m，碰撞尺寸、硬膨胀、速度、MPPI、Rotation Shim 和倒车模式没有改动。没有改地图或删除障碍。
- 启用延期终点扩展集合时，会清除旧集合的组件剪枝并允许相关起点重试；总次数和时间预算不重置。

本机 Release 编译 `astar_3d_planner`、`navigation_bringup` 成功。完整软件检查：规划器 220 项、导航插件加载 1 项全部通过，无失败、错误或禁用项。新增 15 项检查包含在这个总数内，不是新增真机趟数。

| 构造场景 | 检查结果 |
| --- | --- |
| 首选支撑孤立，另一地面支路连通原目标 | 原代码抛不连通异常，修改后到达原目标 XY |
| 同一孤立支撑片包含超过 8 个候选 | 跳过已穷尽组件，能检查另一连通支路 |
| 实际机器人已有地面、前方存在地面大缺口 | 仍拒绝跨越 |
| 墙体分隔或目标在更高且不可连接的地面层 | 仍拒绝规划 |
| 在线模式不启用离线盲区连接 | 安全备选起点重试通过 |
| 首选终点静态姿态能放下，但完整末端旋转碰撞 | 单坏终点朝向搜索失败，多候选能到安全终点 |
| 普通终点恢复关闭朝向搜索 | 仍能在同一起点保留其他完整可行终点 |
| 精确目标静态可放下、完整进入转向不可行 | 启用延期位置，返回容差内且矩形完整检查通过的终点 |
| 全部终点的完整末端转向都碰撞 | 多目标搜索仍失败 |
| 普通搜索超时、达到节点上限或只在朝向上失败 | 不生成可达组件剪枝，避免错误排除后续起点 |

多终点几何回归使用软件构造的 0.8 × 0.5 m 矩形、0.05 m 网格和 0.48 m 测试目标半径，目的是稳定复现两个终点的取舍。这些值只在测试 fixture 中使用，不是对真机参数的调整或建议。业务 0.2 m 目标半径保持不变。

调试中发现并修正两处问题：初版负例中的墙与直达路线平行，不能证明被墙分隔，改成真正分隔两侧的墙；延期终点过早激活导致两个检查提前停在容差边缘，已调整为原终点及其安全起点优先，独立重跑 9 个重点插件案例后全部通过。最终以 `tests_full.log` 的完整检查为准。

此前日志中“已生成路径后无进展、数据过期取消”的执行故障不由本轮回归证明解决。本轮验证的是全局规划候选恢复和拒绝边界，不能换算成真机通行成功率。
