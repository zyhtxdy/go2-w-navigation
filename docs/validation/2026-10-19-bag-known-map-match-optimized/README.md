# 本机已知地图匹配优化

本次没有连接 NX；没有启动导航控制器、运动桥接、真实驱动或发送运动请求。使用独立 Domain 114 和 localhost。

## 改动

- 全局候选中增加一个由最近新鲜有效定位与同时间里程计预测的初值。保留原检索候选数量、每轮全局复核、质量、可观测性和歧义门槛。预测不作为位置真值。
- 重定位发布高质量待确认候选，适配器按诊断的同时间戳先执行独立 LIO/EKF 和连续性检查。上游未 valid 前不发布定位 TF，也不开放速度。两处原有三帧确认可以重叠，位置跳变、低质量、超时仍清除确认。兼容没有候选话题的旧节点，采用原串行流程。
- 增加综合分数及阈值/余量、收敛状态、不同位置备选分差、预测是否使用和候选标识等诊断。
- 未指定 CMake 构建类型时采用 Release；显式 Debug 等选项仍受尊重。
- 回放验证工具保存有效 map→odom 变换，便于内部一致性对照。

## 相同 bag/地图的对照

输入：`bags/go2_inputs_20261010_094309`，地图：`maps/lab_v1_database` 与 `maps/lab_v1_navigation`。每个版本完整回放 1 次，共约 68.9 秒/次，非真机行走测试。

| 指标 | 修改前 | 修改后 |
| --- | --- | --- |
| 首次导航就绪 | 6.49 s | 4.07 s |
| 导航就绪时长（含启动阶段） | 49.12 s | 64.84 s |
| 就绪时间占整段包比例 | 71.3% | 94.1% |
| 不同时间戳有效匹配数 | 53 | 62 |
| 有效匹配耗时中位数 | 766.4 ms | 755.0 ms |
| 有效匹配内点残差中位数 | 0.093 m | 0.093 m |

修改后这次回放从首次 ready 到回放结束保持 ready；没有中途 low_quality、tracking_timeout 或 matching_result_stale。包结束后的 odometry_missing 由输入停止产生。

配准耗时的微小差别不足以证明提速；本轮实证改善主要是定位连续性与确认等待。新增预测初值在 12 个有效测量中成为最高评分候选，但仍经历全部全局质量及歧义检查。

两次回放时间戳不完全相同。在旧版捕获的 16 个时间位置，对新版 map→odom 进行时间插值（间隔不超过 1.5 s）后，最大平移差约 0.046 m、最大旋转差约 0.0224 rad。这只是两次输出的一致性观察，没有外部真值，不能当作定位精度。

## 验证及限制

重定位、运行时、实际 ROS 节点、适配器和导航取消门控合计 85 项检查通过。包括错误预测不覆盖全局解、重复场景仍拒绝歧义、未确认候选不发有效 TF、重复帧不能凑确认次数、跳变/低质量/过期仍阻断导航，以及旧任务取消流程。

动态障碍功能测试将自身的碰撞半径固定为原场景所需值，避免与本次之前的窄通道生产参数调优耦合；没有改动生产规划半径或 A* 算法。

没有降低 0.70 综合分数门槛，没有减少确认帧数，没有扩大 3 秒新鲜度/超时门槛，没有降低全局复核频率。尚未验证 NX 运行耗时、搬动恢复的真实效果或真实隧道误定位风险；就绪时长不是导航成功率。没有同步 NX。
