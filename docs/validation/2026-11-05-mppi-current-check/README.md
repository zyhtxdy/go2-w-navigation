## 方法

沿用 11-03 从 NX 读取的真实原始 costmap 中的 56 个致命障碍格，不新增测试场地或障碍。每种配置都调用实际 Nav2 InflationLayer 重建膨胀场，再调用实际 MPPI CostCritic 库评分，不使用此前的近似欧氏膨胀图代替实际插件。

在每个地图格中心测试 32 个朝向，排除矩形顶点越界的姿态；对矩形检查返回致命碰撞254的姿态，各自构造50个相同姿态的诊断候选。分别测试机器人离 MPPI 路径终点3m和0.5m两种评分分支。

这属于冻结地图和评分单元的离线检查，不是真机趟数、不是导航成功率；候选不是实际执行或保证运动学可达的轨迹。

## 判断

当前配置已经消除了这帧地图中“中心为零导致整段跳过”的2610个旧配置样本。但仍有32个边界姿态，矩形检查报告碰撞，而 CostCritic 没有施加300的碰撞惩罚，只得到约1.425或1.53的软代价；近终点分支下这些软代价为0。这里的300来自当前评分归一化：3.81/254×1000000/50。

剩余样本的中心代价为95或102。按当前轮廓，外接半径为 0.471699057 m，评分器的中心代价快捷阈值约103；中心低于阈值时不做矩形检查。但栅格离散后的轮廓边界仍可能覆盖致命障碍格。这是另一层快捷判断与直接矩形栅格检查不一致。

把 radius 从0.5加到0.55，32个样本仍然存在。因此不能声称继续扩大到0.55就完整修复了代码逻辑；此前“0.55更稳”的建议仅有覆盖范围意义，不能作为消除全部漏检的保证。

本次没有验证完整MPPI闭环绕行，也没有证明这32个姿态出现在实际行走中。配置有明确改善，但碰撞评分一致性尚未全部通过。
