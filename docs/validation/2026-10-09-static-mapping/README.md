## 时间检查与修改

原驱动设置 `use_timestamp_type=0` 时，10 秒原时钟检查（1 次，0 趟运动）收到 101 帧；
帧头和逐点 timestamp 均为 2020 年时间，而 NX 系统时间为 2026 年。
因此改为 `use_timestamp_type=1`，由禾赛 SDK 使用 NX UDP 接收时间同时生成帧头和逐点时间。
本体 `/lowstate` 无绝对采样 Header，桥接继续使用 NX 回调接收时间。
没有修改 NX 或机器狗的系统时间、网卡、路由、DDS 配置文件。

修正后两个测试的帧头、逐点时间、本体 IMU 和 LIO 输出均在 NX 系统时间基准内，未观察到时间戳倒退。
这证明初期软件时钟可以配对，不证明硬件采样同步或网络时延已经标定。

下面为 60 秒测试（1 次，0 趟运动）的观察值，年龄指本订阅者接收时刻减去消息时间戳，不能当作采样误差：

| 消息 | 收到的数量 | 接收频率观察值 | 时间戳年龄中位数 | 倒退次数 |
|---|---|---|---|---|
| XT16 点云 | 597 帧 | 10.027 Hz | 161.98 ms | 0 |
| 本体 IMU 桥接输出 | 29809 条 | 500.149 Hz | 0.53 ms | 0 |
| FAST-LIO 里程计 | 585 条 | 9.999 Hz | 75.52 ms | 0 |

点云 header 为帧起始时间，逐点时间覆盖该帧；LIO 里程计使用帧结束时间。
因此点云 header、本体 IMU header 和里程计 header 不应要求逐条完全相等。

## 退出问题与处理
