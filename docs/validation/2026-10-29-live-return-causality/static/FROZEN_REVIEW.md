# 冻结规划对照的独立只读复核

审查对象为同级 `../frozen/prepare_inputs.py`、`audit.cpp` 和 `build_harness.py`。
未编辑这些文件，没有连接 NX、启动运动或修改业务源文件。

## 可以用于什么结论

当前夹具读取最终回放的 GridBased 参数；使用原固定图、0.01 m padding 后的
0.82×0.52 m 外廓、同一冻结起点／目标、真实 OccupyMap 和当前 SweptFootprint 策略。
实时原 CDR 经真实 `transformCloudObservations` 解码，保留来源与逐点观测时间；
更新地图后按原 0.6 s 规则做体素过期，未发现把整批旧点按单点时间错误删除的行为。
点步长为 1，与实际参数一致。

调用真实 `computePlan`，隔离身份校验、ROS 发现及健康心跳门控，适合比较：
**这些冻结几何输入中，加入对应实时云是否改变求路结果。**
开始地面高度直接使用原失败诊断，避免需要另启 LIO 并重新估计高度。
`use_sim_time=false` 使诊断日志使用墙钟，但地图过期由显式原包时刻控制，
不能把日志墙钟再误当作原包中的人员经过时刻。

## 必须保留的忠实度边界

1. 生产离线 `transformCloud` 使用最新 map←odom TF，准备脚本使用保存的源时刻 TF。
   12 个“同头时间原 CDR”中：10 个首碰点近乎精确恢复，索引 79 差约 0.08 mm，
   索引 91 差约 1.934 cm。后者应单列为近似恢复，不能声称整批是位级原快照。
2. 起点取原客户端 `start_tf` 的 XY／四元数，地面高度取原失败诊断。
   索引 47 的 XY 与诊断记录差约 4.72 mm，索引 175 差约 7.75 mm；其余不足 3 mm。
   A/B 使用同一冻结位姿，因此相互对照成立，但不是原服务端输入的严格位级重演。
3. 该夹具不包含 `createPlan` 返回前的最新地图二次复核。
   索引 90 原先发生在该阶段；把最新云用于重新规划，可以检验是否另有路径，
   不能恢复原先已算好但被否决的那条路径，也不能据 B 成功否定原动态否决事件。
4. 一次原始云只代表对应快照，不能精确替代未保存的所有历史输入／并发更新。
5. 独立补采来自另一次 SLAM／定位回放，其 TF 和筛选结果可能不同，必须与原 CDR 分开统计。
6. 搜索有时间与数量限制。A/B 的成功／失败若跨重复运行不稳定，不能据单次结果作唯一原因归属。
7. 该方法不能给动态点赋予“人”的语义；即使加入实时云后失败，也只证明实时观测有影响。

以上没有发现需要否定整个冻结几何对照的重大错误，但限制应随最终计数一起公开。
