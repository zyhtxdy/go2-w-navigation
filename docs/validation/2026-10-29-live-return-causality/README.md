# 失败是否由经过的行人造成：本机验证

2026-10-29。只读取本机原地图、原录包和上轮失败记录，使用隔离诊断进程验证。
没有连接 NX、修改导航业务源码或参数、运行控制器或发布机器人运动请求。

## 结论

**实时点云确实会影响部分规划，但现有证据不支持把大部分失败归因于临时路人。**
没有任何点簇被确认是人。下面的计数均按软件请求统计，同一位置、不同朝向和时刻会重复出现，
不是真机趟数，也不是独立人员或物体数量。

## 冻结输入对照

固定每个原失败请求的起点、目标、朝向、地面参考和相同固定图，使用当前实际规划配置，比较：

- A：仅固定地图。
- B：固定地图加实时障碍快照。

复用真实 `OccupyMap`、点云解码、0.6 秒按体素过期处理、外廓配置和 `computePlan` 核心。
仅隔离 ROS 身份、健康和心跳门控，不改变几何判定或搜索预算。
冻结的是几何与观测过期参考时间，不是整个 ROS 运行时钟。

| 对照 | 结果 |
| --- | --- |
| 全部 35 个失败请求，仅固定图 | 28 个仍被拒绝，7 个返回路径 |
| 12 个有保存原始源云的重建对照 | 2 个由 A 成功变成 B 失败；9 个两边都失败；1 个两边都成功 |
| 全部 35 个请求，加入独立补采快照 | 5 个由 A 成功变成 B 失败；27 个两边都失败；2 个两边都成功；1 个反向变化 |

原始源云重建中，索引 **79、81** 出现 A 成功、B 失败。
独立补采对照中，索引 **9、11、79、81、123** 出现该变化。
这说明这些冻结输入中的实时观测确实会改变求路结果，**不说明观测物体就是人**。

主对照 82 组输入各重复两次，共 164 次查询，重复结果一致，没有诊断程序错误。
13 个固定图首证据请求另做最近新鲜帧敏感性对照，状态与主选帧完全一致。
索引 32 在独立补采对照中出现 A 失败、B 成功，反映有限搜索、终点选择和代价变化；
不能解释成新增障碍在物理上打开了通道。搜索拒绝不构成穷尽空间后的无路证明。

## 回波时序与固定图

原来保留的完整窗口只有 8 个，因此又用原传感器包做了一次独立回放，补全全部 22 个
实时首碰请求前后各 3 秒的点云。补采有 644 帧有效配准点云和 253 帧有效实测障碍。
40 条 TF 错误均在 1.24～3.94 秒启动期，不涉及最早约 11.66 秒开始的失败窗口。

- 按 15 cm 邻域检查，20 个窗口持续有附近回波，103 对半径敏感，90 间歇出现。
- 扩大到 20 cm 后，21 个窗口持续有附近回波，90 仍间歇。
- 90 的命中率约为 40.7%／45.8%，可能涉及动态物体，也可能是视角或遮挡变化。
- 持续回波不能排除站立的人，缺少回波不能证明人已离开或空间自由。

固定图本来就有一条靠近目标行 `y=0.4` 的占用带。
22 个实时首碰点到保存的实测点的最近三维距离为 **3.64～14.01 cm**；
但只有 1 个落在同一 10 cm 体素，不能把接近说成同一个点或同一个物体。
13 个固定图首碰证据均对应保存的实测点，而非合成危险标记。

## 还原边界

- 原始录包只有雷达、IMU 和运动状态，没有同步视频或人体语义标签。
- 生产离线点云处理使用最新 TF；保存证据使用源时刻 TF。
  多数源云重建的首碰点接近原记录，但索引 91 约差 1.934 cm，不能称位级历史复现。
- 起点客户端记录与服务端诊断有毫米差异；A/B 内部保持完全相同。
- 独立补采来自同一原始录包，但重新估计的配准和定位可能不同，单独统计，不能冒充原快照。
- `computePlan` 对照不包含 `createPlan` 最后的最新地图复核。
  特别是索引 90，原来那条已算出的路径被新快照否决；重新规划成功不否认该历史事件。
- 固定图仍拒绝的 28 组说明当前实时回波不是这次软件拒绝的必要条件，
  不证明固定地图一定正确，也不能排除建图时人体回波残留、误分类或坐标误差。
