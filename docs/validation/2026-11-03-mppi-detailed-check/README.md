## 2. 0.35 仍存在具体的中心零代价漏检条件

按当前配置（矩形 ±0.40、±0.25 m，加 padding 约 0.01 m），外接半径约 0.48549 m。0.35 小于这一范围。

部署的 MPPI 版本 1.1.20 的 CostCritic.score() 在中心点 cost<1 时直接 continue，位于 footprint 检查之前：
https://github.com/ros-navigation/navigation2/blob/1.1.20/nav2_mppi_controller/src/critics/cost_critic.cpp

从 NX 原样读取一帧 /local_costmap/costmap_raw（80×80），其中 56 个致命障碍格、1067 个内切代价格、192 个软代价格、5085 个零代价格。说明 0.35 已产生软梯度，但尚不足以覆盖当前矩形。

离线程序调用 Nav2 C++ FootprintCollisionChecker，针对零代价中心格，以 32 个朝向检查矩形。所有矩形顶点均要求在地图内，排除边界导致的碰撞。

| 冻结地图排查项 | 结果 |
|---|---|
| 地图内零代价中心采样姿态 | 99,056 |
| 其中矩形检查返回致命碰撞 254 | 2,610 |
| 会被中心零代价快捷分支跳过的上述姿态 | 2,610 |

这是 1 帧真实 costmap 上的离线姿态采样，不是真机行驶趟数、不是碰撞概率，也不是成功率。它证实配置与快捷碰撞判断之间存在风险，不能证明当时真实执行轨迹恰好命中这些姿态。

示例：中心 odom=(1.125,-0.975)，yaw=3.53429 rad，中心代价=0，而矩形轮廓代价=254。这是离线候选姿态，不是实际机器狗所在姿态。

## 5. 另一个评分设置

CostCritic.near_goal_distance=1.0。该版本在机器人距离 MPPI 当前使用的路径终点 1 m 内关闭 preferential 软代价项；致命碰撞和 critical 分支保留。这个终点可能是 MPPI 裁剪后的局部路径终点，并非总能等同于完整导航目标。

这会削弱接近终点时对软梯度的偏好，但不能仅凭参数认定当时进入了这个分支，也不能说 MPPI 所有避障都被关闭。
