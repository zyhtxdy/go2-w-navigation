## 已确认的代码关系

每次新路径都会调用 RotationShimController::setPlan() 并把 path_updated_ 置 true。下一次控制会根据新路径的近处采样点重新判断是否需要先旋转；若接管则该周期直接返回 Shim 的速度，不调用 MPPI。MPPI 自身超过 reset_period 没被调用时也会重置优化器，所以 Optimizer reset 不能单独证明求解失败。

因此这里有一条需要验证的交互：动态障碍导致全局重规划 → 更新路径 → Shim 重新判断接管 → MPPI 避障可能被反复打断。当前日志没有控制权和候选轨迹评分，尚未证明这一链条的每一步均在当时发生。

## 对此前结论的修正

此前两次较早事件中存在 FollowPath 被取消并等待恢复，但刚停止的最后一趟只有路径更新，没有对应取消日志。不能把较早事件的“停止了局部跟踪”直接套用到这趟。

冻结地图的中心零代价漏检是另一个可复现风险，不是这趟没有绕行的已证实原因；参数回退是用户主动操作，不是系统异常。
