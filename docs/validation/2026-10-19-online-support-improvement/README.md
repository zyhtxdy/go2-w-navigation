# 在线规划支撑与地面拟合改进（2026-10-19）

算法修改与验证阶段只在本机进行，真机运动测试 0 趟。随后按用户授权，将 14 个改动文件同步到本人 NX 容器；详见文末同步记录。没有在 NX 编译或启停节点。

## 改了什么

- 支撑格的 XY 输入、重叠匹配和查询统一使用严格有界的 FLOAT32 边界归一化。0.2 m 的相邻地形格不再因传输舍入变成 0.3 m 图间距；障碍仍用原来的量化和膨胀。
- 历史支撑层按实际米制高度差关联；连续高度跨 Z 格时重新索引。更新在整帧独占锁内完成，不产生读者可见的空列。没有增加时间平滑，也没有填补未知地面；同一体素无法区分任意近的两个高度层。
- 地面拟合让每个独立 XY 格参与共识，抑制局部高回波对平面的拉偏。污染邻域从低残差层抽取最多 8 个分散锚点，最多 56 个三点候选；候选需要至少 60% 独立格一致，不能覆盖掉显著低层。干净平面保留直接拟合快路径。
- 支撑信心只计真实近平面回波；当前格没有地面回波时，邻域平面不能凭空生成该格支撑。真实坡面、正负台阶、坑和实际离地障碍的检查保留。
- 路径坡度/台阶拒绝记录实际两端支撑键、高度和水平距离，后续可直接核查假陡坡，而不是只看到 `ground_disconnected`。

本次没有改传感器、FAST-LIO、EKF、速度、入口 launch、坡度/台阶门槛、0.25 m 连接半径或危险点稳定器。

## 地面拟合与耗时

同一旧图 8,527 点，在 origin 窗口的算法输出：支撑格 208→271，合成危险标记 997→708。之前被错误拟合成约 18.78° 的 origin 地面恢复为支撑高度 -0.34183 m。这些是算法观察结果，没有外部地面/障碍真值，不能直接当作物理精度或导航成功率。

5 个窗口、每个 10 次的最终本机 `-O3` 拟合中位耗时为 2.93～4.88 ms，最坏 4.95 ms。旧源码 `-O3` 的前次批次为 1.23～1.74 ms；另有同批次旧安装静态库对照 1.28～1.87 ms，其原始优化参数没有重建确认。完整在线回放日志各抽样 33 次，分析耗时中位数为 2.195→4.060 ms，最大为 3.479→5.899 ms。算法开销确实增加；以上均为笔记本观察值，不能代表 NX。
