# 2026-10-29 导航补丁一致性复核

已在本机修复确认的不一致，并完成编译、回归和录包验证。本轮没有连接 NX、启动运动桥接或发送运动 API 请求，真机测试 0 趟。

## 结论

确实存在几处不同补丁之间没有贯彻到底的问题，最直接的一处是：规划器返回了经过验证的路径，随后重写时间戳，却没有同步缓存；行为树再检查同一条路径时，丢失了原来选定的起点支撑依据。另一处是障碍点范围已经精化，前置硬预筛却仍按完整体素提前否决。

本轮统一这些分支及其数据生命周期。当前默认仍为全局几何引导路径、Rotation Shim 加前进 MPPI；没有加入倒车策略，没有重新调整线速度、角速度补偿或车身尺寸。

## 修复清单

| 确认的问题 | 本轮处理 | 回归依据 |
| --- | --- | --- |
| 完整体素硬预筛与精化后的障碍范围不一致 | 预筛使用与末端检查相容的必要条件，不能提前否决精化明确允许的位姿 | 亚栅格、负坐标、不同朝向及原数值反例 |
| 固定地图发布时丢失实测／合成来源 | 从通过校验的 hazard_sources.csv 恢复逐点来源，传到规划器；未知、合成及混合体素保持完整检查 | 地图服务器实际消息、内容哈希、标签篡改、混合来源 |
| 固定地图还受实时输入的 point_stride 影响 | 固定支撑及固定障碍保留全部点；实时输入原有步长保留 | stride=3 时第二个固定碰撞点仍必须被拒绝 |
| 同一实时体素持续命中时永久保留旧范围极值和旧来源 | 按原有 accepted-update 保留窗口淘汰旧观测，范围、来源及诊断同步更新 | 旧离群值／unknown 退出、固定与动态混合、替换及过期 |
| 返回路径时间戳／重连后缀与缓存不一致；直线路径漏存起点依据 | 缓存精确对应实际返回路径，保留本次已验证起点；不复活已被地图更新清除的缓存 | 真实公开规划入口、直线、稀疏起点连接、重用后缀 |
| 启动运动被 IMU 校正节点当作永久零偏 | 连续静止窗口通过才固定零偏；之前透传原始角速度 | 运动、间断、时间回退、慢速恒转姿态检测及真实回调 |
| LIO 输入帧不符仍被重贴标签送入融合 | 错误世界帧／机身帧直接拒绝 | 已装入有效静态 TF 的真实回调负对照 |
| 在线局部感知停更，costmap 永不变旧 | marking 和 clearing 两路 expected_update_rate 设为 0.8 秒 | 配置检查与完整链路感知停更注入 |
| 已结束任务残留非零运动历史，后续输入故障触发旧任务恢复 | 只凭本次任务真实终止、零指令及安静窗口清理历史；缺证据仍保持原保护 | 重复终止消息负对照、主动取消后的空闲断流 |
| 离线入口的前进补偿开关未传给自身桥接 | 显式声明并传递 forward_compensation，默认 true | 前进／转向开关四种组合的真实 launch 构造 |

IMU 静止窗口的软件初值为：至少 400 条且持续 1 秒、角速度模长 ≤0.05 rad/s、每轴方差 ≤0.0002、有效姿态变化 ≤0.01 rad、最大样本间隔 0.1 秒。它不是硬件标定结论。FAST-LIO 本身仍需静止启动；本轮没有修改其初始化算法。

## 当前两条链路的职责

- 在线：FAST-LIO、融合及地形模块运行；全局规划器累计收到的地形支撑，实时更新障碍；fusion 发布恒等 map→odom。
- 离线：FAST-LIO、融合及实时地形仍运行；支撑和固定障碍由离线地图提供；新鲜实测障碍叠加到全局检查；局部控制仍消费实时地形；重定位模块拥有 map→odom。
- 在线输入必须保持支撑／障碍同帧配对以做高度补偿；离线固定地图禁用这项高度补偿。
- 同一次运行只保留一个 odom→base_link 的融合发布者、一个 map→odom 所有者。离线总入口启动里程计时已关闭 fusion 的恒等 map→odom。
- 搜索、最新地图复核、路径有效性服务及缓存采用同一套矩形／点范围规则。全局 guidance 不检查每个路径折点的原地转向圆弧，局部控制继续检查其实际预测轨迹。

## 地图来源格式的兼容

磁盘 navigation_map.json 的 format_version=1、原地图 CSV、数据库及目标清单未改。来源仅采信元数据中已有哈希校验的 hazard_sources.csv；缺失、未匹配或冲突的标签为 unknown。

固定障碍 ROS 消息变为 16 字节记录：XYZ FLOAT32、obstacle_source UINT8、3 个零填充字节；support 仍为 XYZ 12 字节。运行时 map_id 使用 schema 2，完整哈希包含来源字节。旧目标清单通过独立的 geometry_id 识别同一份原几何，运行时固定地图保护仍验证完整新 map_id 和消息哈希。

因此部署时地图服务器、Python 启动代码和 C++ 规划器需要一同更新。旧地图缺少可靠来源时保留保守检查，不擅自将其全部标成实测点。

同一包 go2_inputs_20261010_094309、lab_v1_database、navigation_candidate 及原目标清单，10／30／50 秒三个批次，隔离域 197：

冻结同一原地图、不带实时回波的 16 个历史绕行请求：当前组合 16/16 返回路径，14/16 接近实际端点直线。独立启用全图精化但仍要求严格原地转向的对照为 15/16；没有将它冒充当前默认组合。详见 frozen_geometry_results.json。
