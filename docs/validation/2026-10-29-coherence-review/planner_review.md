# 全局规划补丁一致性审查

2026-10-29，基于审查开始时工作区源码。仅阅读和数值几何核对，没有修改业务源码、编译、启动 ROS、连接 NX 或运动。

## 1. P1：精化几何与硬预筛的必要性证明不一致

- `occupy_map.cpp:49-64` 的内切圆预筛仍以完整原体素作为障碍。
- `swept_footprint.cpp:104-136` 在精化开启时，以该体素内保存点 AABB 加余量作为有效障碍。
- 原来的“预筛拒绝是所有矩形朝向下都必要的”证明只对完整体素成立，不能直接推广到较小的点范围。

数值反例使用当前 10 cm 分辨率、0.26 m 内切半径和加 padding 后的 ±0.41/±0.26 m 外廓：

| 项目 | 值 |
| --- | --- |
| 机器人地面位置 | (0.05, 0.05, 0.01) m |
| 静态障碍保存点 | (0.299, 0.199, 0.225) m |
| 机器人 yaw | 2.1100337945 rad |
| 源体素相对目标格偏移 | (2, 1) |
| 预筛中心距离 | 0.223606798 m，低于 0.26 m，因此拒绝 |
| 点范围＋2 cm 后的矩形 SAT 短轴间隙 | 0.002744163 m，位姿可以分离 |

这是代码与数值几何反例，未调用 C++ 检查器，数值脚本结果在 `planner/read_only_checks.json`。
它证明单个位姿可被精化检查放行，但在更早的 `traversableOnSurface`／目标投影中就被粗几何拒绝。
它不声称该反例的一整段带采样余量的运动也已经验证通过。

**明天影响：** 某些精确目标和支撑格仍可能被报 `goal_body_clearance_blocked`，新精化没有执行机会；
后续再加目标偏移、亚栅格或缓存宽限只是绕开同一个根因，可能继续出现不必要的终点偏移与绕行。

**最小修复方向：** 让预筛基于同一精化几何给出真正的必要条件，或启用精化时停止使用旧的完整体素硬预筛，
只保留软代价和最终完整矩形检查。若需要保留一个保守但便宜的硬核，可从最坏子格偏移推导缩小后的必要核，
而不是继续沿用原半径；核退化时应为空，不能仍强行阻塞源格。

**缺少的测试：** 同一地图、同一位姿下，粗预筛不能拒绝明确由当前精化模型认可的矩形位姿；覆盖亚栅格偏移和不同 yaw。

## 2. P1：返回路径重打时间戳后，起点连接见证无法匹配

- `computePlan` 内 `cachePath` 保存一份路径，搜索分支约 `astar_3d_planner.cpp:2136` 还保存实际验证的 `start_key`。
- 离线 `createPlan:954-955` 最新地图复核通过后，又重写返回路径及各 Pose 的时间戳，没有同步刷新缓存。
- `evaluateTerrainPath:2361` 只有在 `cached_output_path_ == path` 完全相等时才保留已验证的起点连接。
- 直接直线分支 `1333-1334` 的 `cachePath` 没有传 `verified_start`，使 `cached_start_valid_` 始终为 false。

**触发条件：** 时间推进一次就能破坏搜索分支的完整消息相等性；直接分支则无须时间推进。
当实际成功路线使用替代支撑格／其他连通分量的起点时，服务重新投影可能选回已失败的原候选。

**明天影响：** 规划器返回成功，但 BT 路径有效性服务立刻失效，出现反复重规划、停车或取消。
在简单支撑图上重新投影恰好成功时不会显现，所以“某个服务测试通过”不足以覆盖该问题。

**最小修复方向：** 最新地图验证和时间戳统一完成后，用最终实际返回路径及 `checked_start` 原子刷新缓存／见证。
直接路径也必须传经过验证的起点。不得仅取消消息相等限制而让任意外来路径获得盲区豁免。

**测试缺口：** 已有 `SavedSparseMapRetainsSelectedStartConnector`（test_offline_goal_selection.cpp:302）只装支撑，
重新投影也可能成功，没有强制验证“必须保留实际替代 key”的情况。应覆盖真实时钟推进、直接路径、替代起点、
原路径与篡改路径，并确保刚返回的同一条路径能通过实际服务。

## 3. P2：静态图保留了所有点，却丢失实测／合成语义

- `map_server.py:51` 发布 `cloud_message(self.obstacles, stamp)`。
- `map_io.py:164-178` 的消息仅包含 XYZ。
- `OccupyMap::setStaticObstacles:611-624` 将所有点统一标为 `kStaticMap`，保存相同的点范围。
- `staticObstacleBoundsUnlocked:720` 不区分原始实测点和合成危险标记。

当前 `navigation_candidate/hazard_sources.csv` 中，1089 个点有 **618 measured、471 synthetic**。
开启全图静态点范围精化后，这些合成标记也会被当成实际保存点缩小到 AABB＋余量。
“合成／未知仍使用完整体素”的当前约束只对实时来源成立，不能覆盖静态来源。

**明天／后续影响：** 当前平地未证明有实际漏障碍，但合成坡度、台阶或缺支撑危险单元的面积语义可能被缩小，
与以后隧道地形约束不一致。

**最小修复方向：** 静态语义贯穿导出、消息、加载和校验，只有纯 measured 范围可精化，synthetic/unknown 保持整格。
如果暂不完善该链路，应明确限制静态精化的适用范围，不能宣称静态合成保护已经贯穿。
注意来源字段加入后应同时核对地图身份摘要是否覆盖实际影响通行的语义，避免只校验 XYZ。

**测试缺口：** 把同一点分别标为静态 measured 和 synthetic，应得到不同的精化许可；旧的未知静态图不能静默获得更宽松语义。

## 4. P2：在线动态范围历史可无限累积

- `occupy_map.cpp:431-442` 每次同体素 incoming 更新，都把旧的 `minimum/maximum/sources` 无条件并入新范围。
- `astar_3d_planner.cpp` 在线更新采用 `replace_dynamic=false`；离线采用 true。
- 没有为这个范围内部的旧极值或来源记录帧号／时间，仅在整个格消失、清除或重置后才删除。

**触发例：** 先观测同一格内的 (0.205,0.05,0.25)，随后一直只观测 (0.29,0.09,0.25)。
只要该格一直有新点，旧 minimum=0.205 就永远不移除；旧 unknown/synthetic 来源也会一直污染精化许可。
代表点时间会刷新，但并集内的旧几何没有对应的有效期。

**明天影响：** 在线长时间运行可能越来越保守，重启后变好；并非点云当前仍然有那条旧回波。
这是代码可推导的长期状态，不是声称已在现场确认该现象。

**最小修复方向：** 确认输入是完整局部快照后，用最新完整快照替换同格范围；或者给范围历史维护明确的帧／时间窗口。
若要保留多个 active 更新，需要能撤销过期极值和来源，不能只依赖更新代表点的时间戳。

**测试缺口：** 现有 `MeasuredBoundsRetainAllPointsAndAllStillActiveUpdates`（test_swept_footprint.cpp:378）只验证并集，
没有验证持续同格更新后过期点的退出。应覆盖 measured→新 measured、unknown→长期 measured，且在线与离线分别验证。

## 已核对且没有直接发现矛盾的部分

- Guidance 和 strict 使用同一 `SweptFootprint` 配置，搜索快照与返回前最新图复核都带当前请求起点。
- Guidance 保留实际起终点位姿与每段矩形通道检查，严格模式保留中间转向圆弧。
- 合并到达朝向时后备搜索将转向代价置零，状态仍保留地面高度层，没有把不同楼层并成二维点。
- 近场精化区域没有在每条搜索边重新归零；最新地图验证和服务以各自真实机器人位置作为区域中心。
- 离线 `createPlan` 采用不可变搜索快照并在最新图重检，避免长搜索阻塞实时更新。

建议优先处理 1、2；3 应明确安全语义，4 应结合明天是否测试在线模式决定优先级。
不要同时重写搜索算法、调整大量速度／恢复参数；先把判定模型和实际返回路径的生命周期统一。
