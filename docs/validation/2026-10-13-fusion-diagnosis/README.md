# EKF 融合修复（2026-10-13）

本次只在本机隔离 ROS 域回放与发布合成传感器数据，没有运动控制、真机测试或目标下发到机器狗。本轮真机运动测试 0 趟。

## 已确认的机制

旧配置的 EKF 未开启迟到量测回溯。一次完整录包调试中，667 次 LIO 位姿处理全部比滤波器当时最新量测更早，迟到约 30～78 ms，中位约 68 ms。约第 58.64 秒开始，LIO 联合 5σ 门限连续拒绝 101 次位姿更新；之后融合位置与 LIO 持续分离。输入各自的时间戳没有倒退，是到达顺序与计算延迟问题。

陀螺仪的原 3σ 预测创新门限也拒绝了许多角速度变化。仅增加回溯仍在录包后段发散；关闭调试的单独对照也出现约 3.77 m 差异，不能把失败归因于调试日志负载。角速度的预测创新包含真实角加速度，并不全是传感器异常。受控有限加速度对照进一步复现其更新迟缓。

历史回溯和联合门控的处理可核对 [robot_localization 官方 ROS 处理代码](https://github.com/cra-ros-pkg/robot_localization/blob/humble-devel/src/ros_filter.cpp) 与 [EKF 门控代码](https://github.com/cra-ros-pkg/robot_localization/blob/humble-devel/src/ekf.cpp)。

## 最终修改

修改融合配置、速度桥接默认坐标与离线回放入口：

- 开启 `smooth_lagged_data: true`，保留 `history_length: 1.0` 秒，先回到测量时刻更新，再重放后续输入。
- 设置 `permit_corrected_publication: false`，保持发布的时间戳向前。
- 移除 `imu0_twist_rejection_threshold: 3.0`，使用默认角速度更新。输入节点的非有限值检查保留。
- 激光位姿 5σ 门限、LIO 桥的平移跳变检查、原协方差、IMU／激光话题与速度指令桥接保持原配置。

- 默认速度模式改为 `body`。原始 Go2W 状态在此录包中已符合机身方向，原桥接再用姿态旋转会反转部分前进／倒退速度；显式 `odom` 模式仍可用于其他核实过的接口。
- 离线入口排除包里旧的 `/go2/odom_raw`，用只读录包桥重新转换原始 `/lf/sportmodestate`。只向 DDS 发布标准 Odometry，避开原始旧消息直接回放失败。原始消息时间戳全零，离线输出使用原记录接收时间近似。

1 秒历史窗口是针对当前录包的起始配置。NX 更大的计算延迟仍需实际核对；本次没有验证 NX 的运行负载。该修改不修复 FAST-LIO 自身的地图漂移或传感器外参误差。

## 速度坐标证据

389 个运动窗口作独立 LIO 位姿差分、转到机身轴比较，原始状态直接使用的 XY 速度差中位范数为 0.042 m/s；旧桥接输出为 0.578 m/s。约第 15 秒，LIO 前向 +0.544、原始 +0.490、旧桥接 −0.466 m/s；倒退段也出现相反符号。这是源间一致性观察，不是外部速度标定，不能推广到所有宇树固件。见 [velocity_review92.json](velocity_review92.json)。

4 秒 FastDDS 原生旧消息回放收到 0 条，发生 1846 次序列化发布失败；把同一帧反序列化后正常发布，桥接收到并正确转换 1 条。只读录包桥据此读取原始 CDR，再发布标准消息。详见 [兼容性测试](raw_state_publish_compatibility.json)。

## 原始录包验证

第一阶段两次独立回放修复了迟到与陀螺仪门控，但仍使用旧方向错误的速度：6/6 路径请求返回直线，14/18 后续检查通过。第 55 秒后仍起点投影失败；同时间戳融合／LIO 位置差峰值仍为 0.34～0.36 m。记录见 [此前两次总结](final_summary.json)，这是速度坐标修正之前的结果。

修正速度与重新读取原始状态后的第一遍完整验证（域 96）处理全部 34359 条原始状态，输出头时间使用原记录时间、没有全零或倒退，正常到达 EOF。相同时间戳插值比较：EKF／LIO 位置差中位约 1.19 cm，P95 约 3.06 cm，峰值约 6.33 cm；朝向差峰值约 0.015 rad。这些是内部一致性观察值，没有外部测量对照。

两次独立验证（域 96／97）均已完成：各处理 34359/34359 条原始状态；同时间戳 EKF／LIO 水平位置差峰值为 6.33／5.51 cm，结束差为 2.64／2.35 cm。6 次固定路径请求中 4 次成功，均为直线；成功路径的 12/12 次后续检查有效。55 秒目标在两遍都被起点投影拒绝。脚下历史支撑存在，近身实测类障碍点的膨胀与起点碰撞拒绝一致；此前快照比请求早约 0.46 秒，尚不能证明内部缓存的确切拒绝点。见 [完整总结](body_final_summary.json)。只调用计算路径接口，不执行导航运动。融合与 LIO 的差值没有外部位置测量对照，不能当定位精度或到点成功率。

旧配置、仅回溯配置的失败记录仍分别保存在 [results.json](results.json)、[debug_smoothed_results.json](debug_smoothed_results.json) 与 [smoothed_results.json](smoothed_results.json)，后续通过结果不会覆盖这些失败。

## 回放启动时钟

原 `rosbag --delay 3` 会在等待期发布推进的 `/clock`，实际播放开始再回跳。新录包桥曾因此提前处理约 3 秒状态，然后按时钟倒退检查退出；该失败保留在 `body_candidate_95_results.json`。入口已改用 launch 的墙钟 TimerAction 延迟启动播放器，等待期没有预播放时钟，正式播放不带 `--delay`。没有靠忽略时钟倒退掩盖这个故障。
