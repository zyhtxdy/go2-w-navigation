# Go2W 倒车朝向与点云漂移检查（2026-10-09）

用户报告：遥控倒车时，RViz 的 FAST-LIO `/Odometry` 箭头与倒车轨迹相差约 90°，积累点云有漂移。
用户随后确认机器人静止。本次仅订阅状态和读取参数，没有下发运动指令，没有改变 NX 宿主机或其他容器。

## 当前已确认

- FAST-LIO 正在使用 `/hesai/points` 和 `/go2/imu`。
- 实际加载外参平移 `[0.1710, 0, 0.0908]` 米，旋转为单位矩阵，关闭在线外参估计。
- 原始本体 IMU、点云和 FAST-LIO 输出位于 NX 接收时间基准；仍不是已标定的采样同步。
- `/Odometry`、`/lio/odom_base` 和 `/odom` 的 yaw 接近，转换及融合没有额外增加约 90°。
- `base_link -> body`、`go2_imu`、`go2_body` 的当前旋转均为零。
- `/cloud_registered` 由 FAST-LIO 自己的位姿生成，EKF 不会反向修复其去畸变或配准。

8 秒静止读取，1 次，0 趟运动；以下是无外部测量对照的观察值：

截图和静止数据还不能确定雷达相对本体的旋转正负号。

## 待核验的雷达轴向

本工作空间禾赛 SDK 的 XT16 解析分支使用 `x = r_xy*sin(azimuth)`、
`y = r_xy*cos(azimuth)`。因此雷达零方位沿自身 +Y，不能仅凭驱动名称假定其 +X 朝狗头。
这也没有证明当前支架使零方位朝狗头；需要用真实前方物体核对。

静止时在狗头正前方放可辨认物体，RViz 使用 `hesai_lidar` 固定帧，
显示 `/hesai/points` 并添加 Axes。记录物体相对原始雷达坐标的方向。
在雷达与本体 +Z 同向的前提下，候选关系为：

| 狗头前方物体的雷达坐标方向 | `R_IMU_LIDAR` 候选偏航 |
|---|---|
| +Y | -90° |
| -Y | +90° |
| +X | 0° |
| -X | 180° |

这里只定义待确认候选值，不是已经完成外参标定。
FAST-LIO 使用 `p_IMU = R_IMU_LIDAR*p_LIDAR + t_IMU_LIDAR`。
不能通过旋转 `body -> base_link` 的显示 TF 来替代算法内部外参修正。
本次在获得实际轴向信息前，没有改动外参，也没有重新启动建图。
