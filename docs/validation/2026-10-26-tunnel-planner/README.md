## 参考与实现

参考了开源 Nav2 Humble 的以下实现思路，保留本项目的分层地形、支撑面与 ROS 接口：

- [Smac Hybrid-A*：朝向状态、转向代价和障碍启发式](https://github.com/ros-navigation/navigation2/blob/humble/nav2_smac_planner/src/node_hybrid.cpp)。本项目在备用搜索中区分到达朝向，为转角计价，并在每次扩展时检查原地转向与直线平移的车身扫掠。动作模型与现有外廓检查一致，没有引入汽车的最小转弯半径约束。
- [Nav2 Theta*：可视直连与路线缩短](https://github.com/ros-navigation/navigation2/blob/humble/nav2_theta_star_planner/src/theta_star.cpp)。本项目对整条候选路线重新验证地面和矩形车身后才接受拉直，并对拐角进行小范围切角。本轮没有把现有搜索替换成完整 Theta*。

最终流程：

1. 保留快速地形 A*、原来的简化及安全备用路线优先级。
2. 可行路线进行受限的拉直与拐角缓和。评分考虑长度和转角；每次变化均重新检查整条路线，保留真实支撑、台阶、坡度、障碍、起点和目标朝向约束。
3. 原有路线和备用连接均不通过外廓检查时，再尝试带朝向的地形搜索。每个位置可保留不同到达朝向；每一步同时检查转向和移动，不再仅依赖中心线找到路后才发现车身不能转。
4. 带朝向搜索使用反向地形 Dijkstra 提供不考虑朝向的代价下界，减少障碍附近的重复扩展。保留地表高度层，不将不同楼层投到一张平面。部分计算只使用已确定的距离及未确定节点的队列前沿下界，不把暂定距离当成下界。

矩形尺寸、padding、硬膨胀半径、地面阈值均未放宽。实时障碍仍参与检查。输出仍为经过采样的折线路径，缓和拐角不等同于连续曲率轨迹，也不保证实车已经能够平顺跟踪。

## 开销与兼容

- 常见可行路线不进入更大的朝向状态搜索。
- 备用朝向搜索默认按稳态时间协作检查 0.35 秒预算；其中反向启发式最多使用 0.07 秒或该预算的 20%。
- 路径优化最多进行 64 次完整检查，并协作检查 0.06 秒预算；达到预算时保留已验证结果。
- 单次地形或外廓检查不能被中途抢占，因此上述预算不是严格实时上限。
- 同一请求内缓存相同平移边的外廓结果；不同入射朝向仍单独检查转向。缓存不跨地图更新复用。
- 有直接支撑的实际起点不被强迫转向几厘米外的栅格中心；已有盲区起步连接保持原约束。

默认参数位于 `nav2_mppi_params.yaml`，插件也提供相同默认值：

```yaml
heading_aware_search: true
path_refinement_enabled: true
turn_cost_weight: 0.15
```

两个开关分别控制备用朝向搜索、路径优化。需要严格对照原行为时同时关闭。源码、启动参数及相应节点需要重新编译或重启后生效。未来同步到 NX 时应保留其现场调参，不能直接覆盖整份参数文件。
