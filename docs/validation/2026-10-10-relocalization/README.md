## 调试中发现的两个问题

1. 核心合成跨地点搬动测试中，共享墙地面让错误局部匹配仍达到
   重叠率约 0.664、RMSE 约 0.156 m。新增综合分数至少 0.70 的保守门槛，
   原测试场景未改，最终明确拒绝旧位置并找到另一关键帧。
2. 实际 ROS 合成搬动流程中，局部配准仍可能以约 0.829 重叠率、
   0.070 m RMSE 接受错误假设。仅靠提高单一分数门槛不能解决；
   初版默认全局复核间隔由 5 s 改为 1 s，与处理间隔一致。
   测试改为持续提供新传感器帧，检查定位撤销后自动搜索并确认真实新位姿，
   没有把断流超时当成搬动探测成功。

这些数字均为合成软件观察值，真机 0 趟，没有外部实物测量对照。

## 保持原链路的依据

仅新增新包及本验证记录。当前三个建图／导航 launch、XT16 配置、Nav2 参数
没有接入或引用新包；SHA256 与实现过程的基线一致，见 `results.json`。
默认不启动新包就不会增加新订阅或配准负载。
独立启动时只订阅当前数据，仍会增加计算和数据传输；NX 资源占用尚未实测。
新 launch 强制关闭 TF，节点也拒绝 `publish_tf=true`，不会替换当前静态 map→odom。

## 尚未验收

- 真实场地任意位置断电重启、搬动、逆向摆放，以及消防点附近的定位精度。
- 真实长隧道沿轴重复结构的混淆率、失效恢复耗时。
- 真正六自由度退化与置信度估计；当前仅有平移法向信息比等几何门控。
- 大型地图关键帧 top-K 检索覆盖率；查询不是穷尽搜索，漏掉重复候选仍可能误判唯一。
- 原地图漂移、雷达／IMU外参与时钟误差对定位的影响。
- NX 单帧耗时、内存和无线可视化负载；当前不承诺机载实时性。
- 固定全局支撑／静态障碍地图保存加载、定位状态与导航启停的集成。

纯几何相同的通道段可能无法单靠点云确定绝对位置；初版会拒绝被检测到的
歧义和退化，不保证识别全部混淆。候选主要搜索 yaw，翻倒姿态未验证。
只有经过真实数据验收并补齐规划地图加载后，才能正式接管离线地图导航。

## 复现

```bash
cd /home/zyhtxdy/go2-w_ws
source /opt/ros/humble/setup.bash
MAKEFLAGS=-j1 CMAKE_BUILD_PARALLEL_LEVEL=1 colcon build --packages-select go2_relocalization --cmake-args -DBUILD_TESTING=ON -DCMAKE_BUILD_TYPE=Release
source install/setup.bash
colcon test --packages-select go2_relocalization --event-handlers console_direct+
colcon test-result --test-result-base build/go2_relocalization --verbose
```

ROS 测试需要允许本机 loopback DDS 通信；不需要狗、NX、外网或 ROS2 录包。
